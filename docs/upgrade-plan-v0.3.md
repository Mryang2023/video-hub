# VideoHub v0.3 升级计划(收藏 · 历史 · UI 优化)

> 制定时间:2026-09-28 晚 · 状态:待排期
> 前置现状:P1~P4 夜间升级已完成(缺陷修复/安全加固/聚合搜索/测试与文档)

## 0. 现状盘点(计划依据)

**已有但用户感知不到的(本次重点是"接出来")**
- 收藏:后端 CRUD 完整、api.js 已封装(`addFavorite/deleteFavorite/getFavorites`),但**前端没有任何按钮调用它**——详情弹窗没有收藏按钮,也没有收藏页面。
- 历史:后端 upsert 去重置顶、上限 200 条;播放器每 10 秒静默保存进度、打开时自动恢复。但**没有历史页面**——头部"观看历史"按钮只是 `router.push('/')` 返回首页。
- 播放器:倍速、画中画、全屏、键盘快捷键、音量记忆、卡顿自动降画质、自动连播下一集——都已实现,缺的是手动画质选择和更顺手的切集方式。

**关键数据缺口(决定多个功能的设计)**
- `WatchRecord` / `Favorite` 里**没有存 `api_url`**。历史页"继续播放"需要该集的播放地址;收藏页"打开详情"需要站点 api。目前只有 `site_key`,需反查。
- 历史记录**没存 `play_url`**(当集地址),续播只能靠 site_key+vod_id 重新进详情选集。

## P0 收藏与历史闭环(最高优先级)

### 1. 详情弹窗收藏按钮
- 文件:`HomeView.vue`、`api.js`
- 做法:弹窗标题栏加星形按钮;打开弹窗时查询是否已收藏(新增后端单查端点 `GET /api/favorites/check?site_key=&vod_id=` 返回 `{favorited: bool}`,避免全量拉取);点击切换收藏/取消,带 Toast 反馈。
- 验收:弹窗内一键收藏/取消,刷新后状态保持;收藏后能在收藏页看到。

### 2. 收藏页 `/favorites`(新页面)
- 文件:新 `views/FavoritesView.vue`、`main.js` 加路由、`App.vue` 加入口(侧栏底部 + 移动端底部导航)
- 功能:网格展示(复用 VideoCard)、显示收藏时间、取消收藏(卡片角标按钮)、空状态引导("去首页发现好片")。
- **打开详情**:点击卡片 → 进入该收藏片所属源的详情弹窗。需要 `api_url`:见第 4 条数据补齐。
- 验收:收藏 → 收藏页可见 → 点击能打开对应源的详情 → 可直接播放。

### 3. 历史页 `/history`(新页面)
- 文件:新 `views/HistoryView.vue`、`main.js` 加路由、`App.vue` 头部按钮改为跳此页
- 功能:
  - 按时间分组:今天 / 7 天内 / 更早(依据 `updated_at`);
  - 卡片:封面 + 剧名 + "看到 第N集 xx:xx / 时长" + 红色进度条(`current_time/duration`)+ 清晰的"继续播放"主按钮;
  - 单条删除(已有端点)+ **清空全部**(新增端点,带确认弹窗);
  - 看完的(进度 ≥95%)显示"已看完"标记。
- 验收:播放一集退出 → 历史页出现带进度的记录 → 点"继续播放"直接从上次进度+上次集数开始。

### 4. 数据补齐(后端,支撑上面两页)
- 文件:`models.py`、`main.py`
- `WatchRecord` 增加 `play_url: str = ""`(保存进度时把当前集地址带上,`PlayerView.saveProgress` 同步加字段);
- `Favorite` 增加 `api_url: str = ""`(`HomeView` 收藏时带上);
- **旧记录兼容**:新增反查端点 `GET /api/site-lookup?site_key=xxx` —— 遍历所有源(优先用站点配置缓存)找到匹配站点,返回 `{api_url, source_id, source_name, site_name}`;前端对没有 `api_url` 的旧记录用它兜底,查不到则提示"源已失效,请重新收藏/重新观看一次"。
- `DELETE /api/history`(清空全部,保留单条删除)。
- 验收:旧历史记录仍能继续播放;新记录直接续播。

## P1 UI 与播放器优化

### 5. 首页"继续观看"横滑区
- `HomeView.vue` 顶部(推荐/分类之上):取历史前 10 条,横向卡片(封面+进度条+第 N 集),点击直接续播;无历史时整块隐藏。
- 验收:首页第一屏出现"继续观看",一键回到上次进度。

### 6. 播放器增强
- 文件:`PlayerView.vue`
  - **手动画质选择**:读 `hls.levels` 生成菜单(自动/具体档位),"自动降画质"逻辑保留为"自动"档;
  - **"下一集"按钮** + **集数抽屉**:集数列表改为右侧可折叠抽屉,全屏时也能唤出切集(现在全屏看不到集数区);
  - 续播提示 toast("已从 12:34 继续播放");
  - 移动端手势:双击左/右半屏快退/快进 10s,双击中间全屏;
  - `saveProgress` 附带 `play_url`(配合第 4 条)。
- 验收:全屏内可切集、可手动锁画质;手机上双击可快进。

### 7. 详情弹窗增强 + 换源播放(聚合搜索的杀手级用法)
- `HomeView.vue` 详情弹窗:大封面、年份/地区/类型标签、简介"展开更多"、收藏按钮(第 1 条);
- **换源搜索**:弹窗底部"在其他源找这部剧"→ 调 `/api/search/all?wd=剧名` → 列出其他源的同名结果 → 点击即用该源的 api 打开详情(源失效/被删时一键换源)。
- 验收:某站挂了,能从详情一键切到另一个源继续看同一部剧。

### 8. 移动端适配
- `App.vue`:≥640px 保持现有侧栏;<640px 用**底部 Tab 导航**(首页/历史/收藏/更多),头部搜索框折叠为图标展开;
- 全局:触控目标 ≥40px、弹窗全屏化(小屏时 detail modal 占满)。
- 验收:手机浏览器访问,四个主页面可达,播放流畅。

### 9. 视觉统一
- 新组件 `EmptyState.vue`(图标+文案+动作按钮)与统一骨架屏,替换现有 4 处分散的空态/加载写法;
- Toast 位置/时长统一,弹窗动画曲线统一。

## P2 源管理与个性化

### 10. 源健康检查
- 后端:`GET /api/sources/health` —— 并发对每源拉站点配置(复用缓存)+ 测第一个站点的 categories 延迟,单源 10s 超时,返回 `[{source_id, ok, latency_ms, site_count, error}]`;
- 前端:源下拉每项加绿/红状态点 + 顶部"一键检测"按钮;失效源标灰并提供一键删除。
- 验收:一键检测能标出全部失效源(本次已验证这类源确实会批量失效,此功能刚需)。

### 11. 设置页 `/settings`
- 后端:`data/settings.json` + `GET/PUT /api/settings`;
- 项:默认倍速、自动连播开关、记录历史开关、主题色(3~4 个预设 accent)、清空历史/收藏数据入口。
- 播放器与相关组件读取设置(localStorage 缓存 + 启动拉取)。

### 12. 配置导入导出
- 导出:sources + favorites + settings 打包为单个 JSON 下载;
- 导入:上传合并(按 id/url 去重)。备份/迁移场景。

### 13. 搜索体验
- 搜索历史(本地 localStorage,输入框聚焦下拉,支持删除单条);
- 聚合搜索翻页:后端已支持 `page`,前端聚合模式加页码控件与"按源筛选"。

## 排期建议(可拆为夜间任务,每阶段一个)

- **第 1 晚:P0(1~4)** —— 收藏/历史闭环 + 数据补齐,体量最小、感知最强;
- **第 2 晚:P1(5~9)** —— 首页继续观看、播放器增强、换源播放、移动端、视觉统一;
- **第 3 晚:P2+P3(10~16)** —— 源健康检查、设置、导入导出、搜索体验、冒烟脚本。

## 风险与注意

1. 旧记录无 api_url:靠 `/api/site-lookup` 兜底,查不到时**明确提示**而不是静默失败;
2. 聚合换源搜索同名片可能匹配到不同剧:结果按"剧名完全一致 > 包含"排序,并显示源名让用户确认;
3. 移动端改动多,构建通过之外建议真机过一遍播放链路;
4. 设置项向后兼容:settings.json 不存在时全部用默认值。
